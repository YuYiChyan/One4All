# 用户操作流程审计 · 2026-11-15

审计基线为独立仓库的 `38ebb9e`（0.7.0-preview.3）。本轮按用户要求检查下载、安装、检测、连接、控制、资源获取、模型适配、反馈和本机启动中的人为限制。目标是让用户发起的操作完成，失败可理解、可取消、可重试。

范围为本仓库的 `app/`、`core/`、`runtime/`、`scripts/` 和 `packaging/`，包括已导入设备页的宿主入口。厂商二进制内部、Windows 自身行为和远端服务的限制不属于本项目可直接改写的逻辑。新增设备的实机状态保持原样，不以软件检查替代实机验证。

| 原行为 | 本轮处理 | 代码 |
| --- | --- | --- |
| 驱动下载十分钟到点中止，单次无响应六十秒就销毁连接 | 移除应用强加的默认时限，加入用户取消；实际网络错误按原错误处理 | `core/vendor-packages.cjs` |
| 超过 2 GiB 的安装包被拒绝 | 删除固定体积上限 | `core/vendor-packages.cjs` |

## 保留条件及实际作用

这些条件不是追加的审批流程，不要求用户进行额外的“安全验收”。

- **设备身份、接口和数据范围**：某个型号的协议不能当作任意 USB 设备的协议；数值、选项和报文格式仍依据适配器提供的实际范围。缺少实现时不给出假控件。
- **单条硬件应答的等待与串行化**：用于识别设备断开、无响应、返回报文归属以及避免同一接口的请求互相串包。与人工选择、下载和模型生成的总时限分开处理。
- **文件实际格式和完整性**：HTML 错误页不能作为 EXE 启动，断流文件不能作为完整安装包，固定版本组件需与该版本一致。失败可重新获取。
- **工作目录范围**：解包、生成草稿、构建输出和卸载只作用于指定目录，避免写错或删错用户已有文件。这不限制正常目录内的文件数量、大小或扫描层数。
- **页面与本机调用的对应关系**：设备页面只调用其对应的本机接口；普通外部链接正常打开。用户界面和厂商网页不获得任意本机脚本执行接口。
- **Windows 文件占用和安装路径**：仍由真实安装文件状态决定能否覆盖，保留既有安装目录和数据目录，升级不清空卡片、配色或反馈设置。
- **本地验证与公开反馈的含义**：待验证标记不阻断使用；实机确认由用户填写，报告不凭软件测试自动改成实机通过。
